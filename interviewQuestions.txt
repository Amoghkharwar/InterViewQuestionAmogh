What is the difference between value type and reference type?
In C#, a **value type** is a data type in which the variable stores its value directly.
When we assign one value-type variable to another value-type variable, a separate copy of the value is created. Therefore, if we change the value of one variable, 
it does not affect the other variable because both variables have independent copies of the data.

For example, `int`, `bool`, `decimal`, `struct`, and `enum` are value types.

int a = 10;
int b = a;

b = 20;

Console.WriteLine(a); // 10
Console.WriteLine(b); // 20

In C#, a **reference type** is a data type in which a variable holds a reference to an object rather than storing the entire object directly.
When we assign one reference-type variable to another, the reference is copied, not the object itself. As a result, both variables can refer to the same object. If we modify the object's properties through one variable, the changes will be visible through the other variable as well.

For example, `class`, `string`, arrays, and interfaces are reference types.

public class Employee
{
    public string Name { get; set; }
}

Employee emp1 = new Employee
{
    Name = "Rahul"
};

Employee emp2 = emp1;

emp2.Name = "Amit";

Console.WriteLine(emp1.Name); // Amit
Console.WriteLine(emp2.Name); // Amit

What is the difference between ref, out, and in parameters?
ref: The variable must be initialized before the method call, and the method can read and modify its value.

out: The variable does not need to be initialized before the method call, but the method must assign a value before returning.

in: The variable must be initialized before the method call, and the method can read it but cannot directly reassign the parameter.

Q: Explain SOLID principles?
These principles were introduced by Robert C. Martin.

SOLID principles help us design applications that are easy to modify, test, and maintain as the project grows.

S - Single Responsibility Principle (SRP)
A class should have only one reason to change.
A class should do only one job.

O - Open/Closed Principle (OCP)
Software entities should be open for extension but closed for modification.
We should be able to add new functionality without changing existing code.

L - Liskov Substitution Principle (LSP)
A child class should be able to replace its parent class without breaking the application.
If a parent object works somewhere, the child object should also work correctly there.

I - Interface Segregation Principle (ISP)
Clients should not be forced to implement methods they do not use.
Create small and specific interfaces instead of one large interface.

D - Dependency Inversion Principle (DIP)
High-level modules should not depend on low-level modules. Both should depend on abstractions.
Depend on interfaces, not concrete classes.

Q: Difference between DELETE, TRUNCATE, and DROP?
DELETE - DELETE is a DML (Data Manipulation Language) command used to remove one or more rows from a table.
TRUNCATE - TRUNCATE is a DDL (Data Definition Language) command used to remove all rows from a table.TRUNCATE quickly removes all data from a table but keeps the table structure for future use.
DROP - DROP permanently removes the table along with all its data, structure, indexes, and constraints.

Q: Clustered vs Non-clustered index?
An Index is a database object that improves the speed of data retrieval from a table

A Clustered Index is an index that physically stores and sorts the table data based on the indexed column. Since the actual data is arranged in sorted order, 
SQL Server can retrieve records much faster. A table can have only one Clustered Index because data can be physically ordered only once. 
In real-world applications, the Primary Key is commonly used as the clustered index because it is unique, frequently searched, 
and provides excellent query performance.

CREATE CLUSTERED INDEX IX_Employee_Id
ON Employee(EmployeeId);

DROP INDEX IX_Employee_Id
ON Employee;

If the Primary Key created the clustered index automatically, you cannot remove it using DROP INDEX.

You cannot remove the index directly using DROP INDEX because the index belongs to the Primary Key constraint.
You must first drop the Primary Key constraint, and SQL Server will automatically remove the associated index.

A Non-Clustered Index does not change the physical order of the data in the table. Instead, it creates a separate structure 
that helps SQL Server quickly locate the required rows.

Think of it like the index at the back of a book. The book pages remain in the same order, but the index tells 
you on which page a particular topic is located.

A Non-Clustered Index is a separate copy of one or more columns that helps SQL Server find data quickly.

Q: Explain normalization.
Normalization is the process of organizing data in a database to reduce data redundancy (duplicate data) and improve data consistency.

1. First Normal Form (1NF)
Rule: Each column should contain only one value (no multiple values in a single column).

2. Second Normal Form (2NF)
Rule: The table should already be in 1NF, and all non-key columns should depend on the entire Primary Key.
Move data that doesn't fully depend on the primary key into another table.
Does every column depend on the entire Primary Key?

3. Third Normal Form (3NF)
Rule: The table should already be in 2NF, and non-key columns should depend only on the Primary Key, not on another non-key column.

Q: Explain different JOIN types?
INNER JOIN - INNER JOIN returns only the records that exist in both tables.
LEFT JOIN - LEFT JOIN returns all records from the left table and matching records from the right table.
RIGHT JOIN - RIGHT JOIN returns all records from the right table and matching records from the left table.
FULL OUTER JOIN - FULL OUTER JOIN returns all records from both tables. If there is no match, SQL Server returns NULL for the missing side.
CROSS JOIN - CROSS JOIN returns every possible combination of rows from both tables.
SELF JOIN - SELF JOIN means joining a table with itself.

Q: Find second highest salary?
WITH SalaryCTE AS
(
    SELECT
        EmployeeName,
        Salary,
        DENSE_RANK() OVER (ORDER BY Salary DESC) AS SalaryRank
    FROM Employee
)
SELECT EmployeeName, Salary
FROM SalaryCTE
WHERE SalaryRank = 2;

RANK() → skips rank after duplicates.
DENSE_RANK() → does not skip rank after duplicates.

Q: Remove duplicate rows?

WITH DuplicateCTE AS
(
    SELECT
        Id,
        Name,
        Email,
        ROW_NUMBER() OVER
        (
            PARTITION BY Name, Email
            ORDER BY Id
        ) AS RowNum
    FROM Employee
)

delete from Employee where Id in (select Id from DuplicateCTE WHERE RowNum > 1;)

Q: Find Employees Who Joined in the Last 30 Days?

SELECT EmployeeId,
       EmployeeName,
       JoiningDate
FROM Employee
WHERE JoiningDate >= DATEADD(DAY, -30, GETDATE());

Q: Explain ROW_NUMBER(), RANK(), DENSE_RANK()?
ROW_NUMBER() gives every row a unique number.
RANK() gives the same rank to duplicate values, but skips the next rank.
DENSE_RANK() gives the same rank to duplicate values but does not skip the next rank.

Q: Explain deadlock?
A deadlock occurs when two or more transactions are waiting for each other to release resources, so none of them can continue.

How to Prevent Deadlocks

Keep transactions short.
Access tables/rows in a consistent order.
Use appropriate indexes to reduce the time locks are held.
Avoid unnecessary operations inside transactions.
Avoid keeping a transaction open while doing external operations.
Investigate blocking and deadlock graphs when troubleshooting.

Q: Explain chunk file upload implementation?
Chunk file upload means dividing a large file into smaller pieces, called chunks, and uploading those chunks separately instead of uploading 
the entire file in a single request. After all chunks are uploaded, the server combines them back into the original file.

Q: How did you handle exceptions globally?
Global exception handling means handling unhandled exceptions at a central place instead of writing try-catch blocks in every Controller or Service method.

I handle unexpected exceptions globally using custom exception-handling middleware. The middleware wraps the request pipeline inside a try-catch block. 
If an unhandled exception occurs in the Controller, Service, or Repository, the middleware catches it, logs the detailed exception using the application's 
logging mechanism, and returns a standardized HTTP response to the client. This avoids writing repetitive try-catch blocks in every method and 
also prevents exposing sensitive exception details to the client.
